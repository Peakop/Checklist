# Doc Checklist

เว็บตรวจเอกสารตาม Document Standard (DS V2.2.0) ของทีม Stealth Trade เลือกชนิดเอกสาร ตรวจทีละข้อ หรืออัปโหลดไฟล์ .docx/.xlsx ให้ระบบติ๊กผลข้อที่ตรวจจากไฟล์ได้ แล้วส่งออกเป็น PDF พร้อมหัวกระดาษและลายเซ็นของทีม

ใช้งานที่ **https://peakop.github.io/Checklist/** (deploy จาก branch `main` อัตโนมัติด้วย GitHub Pages)

## รันในเครื่อง

เว็บเป็นไฟล์ static ไม่ต้อง build แต่ต้องเปิดผ่าน local server เพราะ ES module และการโหลดฟอนต์ใช้ไม่ได้กับการเปิดไฟล์ตรง ๆ (`file://`)

```sh
npm start            # หรือ python -m http.server 8000
```

แล้วเปิด http://localhost:8000 (ใช้ VS Code Live Server แทนก็ได้)

## ทดสอบ

ต้องมี Node.js 22 ขึ้นไป

```sh
npm install          # ครั้งแรกครั้งเดียว ติดตั้งตัวอ่าน XML และ zip สำหรับทดสอบ (เว็บจริงไม่ใช้)
npm test             # ชุดทดสอบหลัก ใช้เอกสารจำลอง
npm run test:fixtures   # ทดสอบกับเอกสารจริงใน tests/fixtures/ (ดูด้านล่าง)
```

`npm run test:fixtures` ใช้ตรวจว่าการแก้โค้ดไม่ทำให้ผลตรวจเอกสารจริงเปลี่ยน วางไฟล์ไว้ที่ `tests/fixtures/` โดยตั้งชื่อตามรูปแบบปกติ (เช่น `2569-10-25_SS_V1.0.0.docx`) ครั้งแรกระบบบันทึกผลไว้ ครั้งต่อไปจะเทียบกับผลที่บันทึกไว้

> **ห้าม commit เอกสารจริงของทีม** repo นี้เป็นสาธารณะ โฟลเดอร์ `tests/fixtures/` จึงอยู่ใน `.gitignore` ชุดทดสอบที่ commit ใช้ข้อความสมมติเท่านั้น

## โครงสร้าง

```
index.html                 HTML ของหน้าเว็บ
css/                       base → layout → components → responsive (โหลดตามลำดับนี้)
js/
  main.js                  จุดเริ่มต้น เรียก init ของแต่ละส่วน
  state.js                 ผลตรวจที่บันทึกในเบราว์เซอร์ (localStorage คีย์ st-doc-checklist-v1)
  config/
    documents.js           รายชื่อเอกสาร หมวด รหัส สมาชิกทีม และกลุ่มเอกสาร (LONG, SHEET, MEETING …)
    checklists.js          รายการตรวจทุกหมวด และ sectionsFor(code) ที่ประกอบชุดตรวจของแต่ละเอกสาร
  ui/                      แถบเอกสาร ฟอร์ม รายการตรวจ สรุปผล หน้าต่างดูตัวอย่าง และ toast
  pdf/                     สร้าง PDF: หัวกระดาษ ลายเซ็น ฟอนต์ และการตัดคำภาษาไทย
  autocheck/
    index.js               รับไฟล์ (เลือกหรือลากวาง) และเติมผลลงรายการตรวจ
    result.js              กฎชื่อไฟล์และเวอร์ชัน (ใช้ร่วมกันทั้ง Word และ Excel)
    secrets.js             ตรวจและซ่อนค่าความลับ
    docx/                  อ่าน .docx และกฎตรวจ (analyze.js) ระดับหัวข้อจากเลขข้อ (levels.js) กฎเฉพาะ Security Standard อยู่ที่ ss-rules.js
    xlsx.js                อ่านและตรวจ .xlsx
  utils/                   ฟังก์ชันช่วยเรื่อง DOM และวันที่ภาษาไทย
assets/                    ภาพหัวและท้ายกระดาษ PDF, ฟอนต์ TH SarabunPSK และลายเซ็นสมาชิก
tests/                     ชุดทดสอบ (node --test)
```

ไลบรารีภายนอกโหลดจาก cdnjs: jsPDF (โหลดพร้อมหน้าเว็บ) และ JSZip (โหลดเมื่ออัปโหลดไฟล์ครั้งแรก)

## งานที่ทำบ่อย

### เพิ่มชนิดเอกสารใหม่
1. `js/config/documents.js`: เพิ่ม `['รหัส', 'ชื่อเอกสาร']` ในหมวดที่เหมาะสมของ `GROUPS` ถ้าเป็นเอกสารยาวที่มีหน้าปก ตารางควบคุมการเปลี่ยนแปลง และสารบัญ ให้เพิ่มรหัสใน `LONG` ด้วย
2. `js/config/checklists.js`: เพิ่ม `case` ใน `contentFor` สำหรับหมวดเนื้อหาเฉพาะเอกสาร
3. ถ้าต้องการตรวจอัตโนมัติ เพิ่มกฎใน `js/autocheck/docx/` (ดูตัวอย่างจาก `ss-rules.js`)
4. `npm run snapshot` แล้วตรวจ `git diff tests/checklist-snapshot.json` ว่าเปลี่ยนเฉพาะเอกสารที่ตั้งใจ จากนั้นรัน `npm test`

### แก้รายการตรวจ
id ของข้อตรวจคือ `key หมวด.ลำดับ` (เช่น `ssx.4`) ผลที่ผู้ใช้บันทึกไว้ผูกกับ id นี้ ถ้าจะเพิ่มข้อให้ต่อท้ายหมวด อย่าแทรกกลาง และอย่าลบข้อเดิม ถ้าต้องตัดข้อออกจากบางเอกสารให้ใช้ `pick()` ซึ่งคง id เดิมไว้

### ออกเวอร์ชันใหม่
1. แก้เลขเวอร์ชันใน `index.html` (ตัวเลขข้างชื่อเว็บ และ `?v=` ท้ายไฟล์ CSS กับ `js/main.js` ทุกจุด ใช้กันเบราว์เซอร์โหลดไฟล์เก่าจาก cache) และใน `package.json`
2. เพิ่มรายการใน `CHANGELOG.md`
3. `npm test` ให้ผ่านก่อน merge เข้า `main`

GitHub Pages เก็บ cache ไฟล์ไว้ประมาณ 10 นาที หลัง deploy ผู้ใช้ที่เปิดหน้าเว็บค้างไว้ควรรีเฟรชอีกครั้ง
